# WittyLog coverage of 0.8.0-alpha

What the log recorded of each new feature before session 10 (audited 2026-11-12), and what it records now. Areas are the `cat` of [Logs](../LOGGING.md#categories-and-levels); sessions are the IDs the viewer's **Follow** uses.

| Feature | Before | Gaps found | Now (area, session) |
|---|---|---|---|
| SDUI and the page editor | Store loading, a page or section that failed to render, config changes, rollback and publish at Info under `ui`, which no area knew, so they fell into Everything else | Validation refusals, 409/412 conflicts, drafts, failed rollbacks, every per-profile change, module data-source failures, legacy content dropped in migration; one message built at run time | `sdui`. Publish and rollback are audit records with `by` and revision. Refusals with the issue count, conflicts with both revisions, drafts, personal pages, layouts and module settings (names, never values; secret values are `AddSecret`ed), what a migration dropped |
| Themes and layouts | Server theme and module colours changed | Uploads, custom themes, deletes and their refusals, colour resets, personal colours, built-in themes or ZIPs that silently failed | `sdui`, each with its refusal reason; the theme manager has a logger |
| Module store and manual overrides | Override installs logged at Warn; audit rows in the database, logged under `gaming` (unknown, so Everything else), without the request | Failed uploads and override installs, upload discarded, password asked for, override kinds missing from fork and source changes; several lines with no area; the SDUI refusal repeated on every resolve | `modules-store`. Every override event is an audit record with `by`, module, version, kinds and grants. SDUI refusals and incomplete-override bypasses once per version |
| Module SDUI loading and refusals | One Warn per resolve, no area of its own | Repetition; `readUI` failures silent | Once per version, with why |
| Profiles and parental controls | Profile switch, wrong parents' PIN, extra time asked for, PIN changed, under `auth` | Refused switches, wrong manager password, an admin giving time, clearing activity, feature and screen-time refusals, a stream cut off when time ran out | `profiles`. Extra time and clearing activity are audit records. The wrong PIN stays in `auth` |
| Remote Protocol | One line when cross-account control changed | Devices announcing, forgetting, connecting and dropping; commands, failures, acknowledgements | `remotectl`, session `rc-<device>`. Hub drops (expired, idle, removed, signed out) through a new hook |
| SyncPlay | Nothing | Rooms, joins and refusals, leaving, host changes, kicks, invites, commands, lag, gate waits that timed out, rooms closing | `remotectl`, session `party-<room>`. Names only: never room codes or member IDs |
| Pairing v2 | Approve, fail, refuse, lock | Pairing start, a bad QR check, the lock after wrong PINs, what the poll saw; `ip` and `from` mixed | `auth`, session = the pairing ID. Never the PIN, `k=` or a token |
| Peer to peer | Node on and off, reachability, refusals, devices added and removed under `auth`, a one-line test result | NAT type, relays, reachable addresses, each device's connection and path, the test's steps; the server's key could fall out of the 64-value secret ring; `s=`, join codes, `X-Witty-Connect` not redacted | `p2p`. Session `p2p-<device short ID>` per device (the device knows it too), `p2p-…` per test. Enrolments, revocations, invites, key changes and settings are audit records. The key is kept with `KeepSecret` |
| Karaoke separation | "Separated", a separator found, job failures with no session | No separator, its stderr and timeout, start and finish, ignored writes | `extras`, session `sep-…` carried into FFmpeg's and the separator's exit lines |
| Canvas and intro jobs | "Canvas made", "intros looked for" | Starts, per-episode failures, ignored saves, no session | `extras`, sessions `canvas-…`, `intro-…` |
| Live TV | Scans, opens, failover success, recordings | Tuner add, change and remove; refresh results; guide sources; health checks; every backup failing; recording schedules and rules. WittyTuner's own lines were all discarded. Xtream catch-up logins (`/timeshift/user/pass/`) not redacted | `tv`. Health checks have session `tvcheck-…` with a summary; recordings `rec-…`. WittyTuner logs with slog on stderr, which the server now reads. A provider refusing the account is a warning, never with the login |
| Disc ranking and analysis | Refusals and failures in the ranking helpers; choices made | Silent open and decode errors, the result, a bare goroutine, the session opening | `discs`, with the ranking's decisions at Debug |
| Readers | Comic open failures | EPUBs that won't open (422s at Info in `http`, off by default), 500s without the error | `library`. The reader modules report through WittyInk's new optional `ReaderHost.report`: a PDF that won't open or is password-protected, a footnote chapter or search that failed, a comic page that won't show (app errors, kind `reader`, with the module). A main EPUB chapter loads in a frame, which says nothing when it fails |
| WittyPlay: libretro sessions | Loaded, ended with stderr, crashes; the helper's lines were Debug "helper says" text with no level, area or session | Session start and end, stop asked, the fallback's session | `games`, the game's session on the server and in the helper |
| WittyPlay: standalone installs | One Warn on failure | Start, success with hash, cancel, hash mismatch, unverified, uninstall; URLs with queries in errors | `emulators`, audit records. Never a login, query or fragment of an address |
| WittyPlay: licences and emulators added by hand | Nothing | Licence accepted, Ryujinx and Lichii identified (how), not recognised | `emulators`, audit records with `by` and how each was identified |
| WittyPlay: sandbox, Docker, native host | Orphans and unattended stops; the native host wrote only its own file | Start and stop with reason, window, encoder, bitrate | `emulators`, with the session |
| WittyPlay: capture and streaming | Encoder, stats every 30 s at Info, relay bitrate | Viewers, relay start, native bitrate changes | Stats at Debug unless slow; viewers and relays at Info |
| WittyPlay: input and settings writes | Nothing | Every save | Debug, topic `settings`: names of what changed, never values |
| WittyPlay: BIOS, keys, firmware | One "found by checksum" line | Presence, the refusal for a missing file | Names present and missing (topic `firmware`); never contents |
| WittyPlay: crashes | Tail logged as `said` | Not read by the viewer's explanations | `stderr`, with key-like hex hidden |
| macOS permissions | Only in Settings and the game's own file | Not in the log | Warn `macOS permission missing`, `permission=screen-recording|accessibility`, with the fix; the viewer explains it, and Repair's Features check says so |
| Apps (Apple, Android, desktop) | Requests, crashes, player errors, some local-only lines | SDUI failures, P2P path changes, remote and party failures, stems on Android under another kind, games without a session | Kinds `sdui`, `p2p`, `karaoke`, `remote`, `party`, `game`, with the same sessions as the server |
| Support bundle and diagnoser | Logs, crash reports, summary, disc reports | Nothing about the newer features | `features.json`; Repair → Features |
