# Design 2: one interface for every platform

Branch `wip/design` (server and WittyMediaClient worktrees `.worktrees/design-*`). Written 2026-11-12. This is the
contract the four design workstreams build against. When this file and a platform's code disagree, this file wins;
change it here first, in the same commit as the code.

Scope: the look, feel and input model of the SDUI renderers on web, desktop, iOS, iPadOS, macOS, visionOS, tvOS,
Android, Android TV and tablets; the shared tokens; the built-in themes; and WittyTV (guide, channels, recordings,
player banner) on the two TV platforms and the web. **Not in scope:** Settings (stays hand-built, same structure and
wording on every platform), and the cast and crew credits on film, show and person pages (S12 owns them; leave those
pages' sections alone and merge `v0.8.0-alpha` often).

**Standing rule: the custom coloured server name.** `brand` parts from the theme engine (`brandAccent`, per-layer) are
drawn in every frame we touch (sidebar, top bar, TV top bar, sign-in, rail header, About). Every workstream's
checklist ends with "the server's name is still drawn from `brand` in every theme and layout".

## 1. What "best in class" means here (the bar)

1. **Content is the interface.** Artwork leads; chrome recedes. Surfaces step by tone (`bg` to `bg4`), never by shadow
   on the page. One accent, used only for "do this next", progress and focus.
2. **One focus language everywhere.** A focus ring in `focus`, concentric with the thing's own corner, plus a lift
   (scale) on media and a fill on controls. Same shape, same motion, same thresholds on a laptop with Tab, a phone with
   a keyboard, a game pad, a TV remote.
3. **Zones, not a maze.** Every screen is at most four zones: **Bar** (top menu or rail), **Stage** (the page),
   **Dock** (persistent controls for that screen, bottom on TV and desktop, sheet on phone), **Layer** (dialog, menu,
   player). Directional input moves inside a zone, between zones by one press, and always has a way back.
4. **The same controls are in the same place** on every screen of a kind. Search is always the last item before You.
   A screen's options are always on one key (see 3) and always in its Dock. Nothing important lives only in a menu.
5. **Fast on modest hardware**, per DESIGN.md "Keeping it fast". Motion: transform and opacity only, 90 to 240 ms.
6. **Accessible first.** WCAG 2.2 AA, targets 24 / 44 touch / 66 TV, `prefers-reduced-motion`, high contrast and
   forced colours, screen readers on every platform.

## 2. Tokens (single source: `themes/tokens.json`, generated by `scripts/design-tokens.py` from `web/src/styles.css`)

Existing sections keep their names and values unless listed. **Changes and additions** (W1 implements; all platforms read):

| Section | Content |
|---|---|
| `type.scale` | Unchanged names. Add `type.role`: `{pageTitle, heading, title, body, caption, label, display}` each `{size, weight, leading, tracking}` for the 1x device, so apps read roles, not the numeric scale. TV roles are in `tv.type`. |
| `space` | Unchanged 4 px grid. Add named steps `none, xs, s, m, l, xl` = 0, 4, 8, 16, 24, 40 (the SDUI spacing steps) so renderers and CSS share them. |
| `elevation` | `0` flat (page), `1` panel (hairline), `2` lifted card, `3` overlay. Each has `fill` (a surface token), `line` (border token or none) and `shadow` (for web and Android; tvOS ignores it). Replaces ad hoc shadows. |
| `focus` | Gain a `style`: `ring-lift` for media, `fill` for controls (fill with `fg`, text `bg`), `ring` for fields. Values per input: `pointer` 2/2/1.0, `keys` 3/3/1.0, `tv` see below. |
| `input` | The key map (section 3) as data: `{keyboard, gamepad, remote}` actions to keys, so every client builds its handlers from one table. |
| `nav` | `{zones, backLadder, bumpers, wrap: false, rememberPerGroup: true, enterFromOutside: "last-or-first"}`; the scoring weights of `spatial.ts` become data (`offLine`, `offCentre`, `leavesLine`) so Swift and Kotlin ports cannot drift. |
| `tv` | TV units (1 unit = 1 pt on Apple TV 1920x1080, 0.5 dp on Android TV 960x540). `safe` 90/60 (x/y), `gutter` 90, `topBar` {height 88, top 24, pill 56, gap 16}, `rail` {closed 120, open 400}, `type` {display 76, pageTitle 57, heading 48, title 38, body 29, caption 25, label 25}, `target` {min 66}, `focus` {ring 4, gap 4, scale 1.06, lift 6, concentric true}, `shelf` {rowGap 56, cardGap 24, peek 0.18 of the next card, padTop 24, padBottom 24}, `card` per style (poster 250x375, wide 420x236, square 300x300, circle 200, channel 280x158), `dock` {height 112, hintSize 25}. Same numbers feed tvOS and Android TV. |
| `layout.breakpoints` | `compact <600, medium <840, expanded <1200, large >=1200` (the SDUI ones) mirrored into CSS as container-query friendly custom properties. |
| `density` | `comfortable` (default), `compact`, `spacious`: multiples of spacing and control height, chosen per profile per device; TV defaults to `comfortable`, desktop to `comfortable`. |
| `motion` | Add `reduced: true` behaviour table: which animations become cuts. Add `focusMove` 120 ms, `screen` 240 ms, `hero` 600 ms crossfade. |

All of it is checked by `design-tokens.py --check`. Swift and Kotlin constants are generated from it
(`apple/WittyKit/Sources/WittyKit/DesignTokens.generated.swift`, `android/.../ui/DesignTokens.generated.kt`) by a
script in the client repo, `scripts/gen-design-tokens.py`, with its own `--check` in CI.

## 3. One input model

| Action | Keyboard | Game pad | TV remote |
|---|---|---|---|
| Move | arrows | D-pad, left stick | D-pad |
| Select | Enter, Space | A / Cross | OK |
| Back | Esc, Backspace, Alt+Left | B / Circle | Back |
| Options for the thing or screen | `.` or Shift+F10, ContextMenu | X / Square (hold A on a card) | long OK, Menu or the options key |
| Search | `/` or Ctrl+K | Y / Triangle | Search key; else the Search pill |
| Previous / next tab | Ctrl+[ and Ctrl+], Page keys in the bar | LB and RB | channel or page keys when the bar has focus |
| Page up / down in a long list, guide, grid | Page Up and Down | LT and RT | channel up and down |
| Jump to top | Home | Right stick click | double Up |
| Play, pause, seek, speed | Space, J K L, arrows | A, bumpers | media keys |
| Open the screen's Dock | `Tab` from Stage when nothing is focused, or the key in section 4 | Start | Menu |
| Help for the keys | `?` | hold Select (Back + Start) | held Menu |

Rules: wrapping never happens, except a Dock's own buttons. Up from the first row of Stage goes to the Bar's current
tab; Down from the Bar goes to where Stage had focus; Back unwinds Layer, then Dock, then Stage to Bar, then Bar to
Home, then leaves. A visible **key legend** (glyphs matched to the connected input) sits in the Dock and is hidden
when there is no pad or remote in use. On touch nothing here shows.

## 4. Screens and where their controls live

- **Bar.** TV: top pills (Home, Libraries, Games, Live TV, Search, more libraries the person chose, You pinned right).
  Desktop and tablet: sidebar, rail, or top tabs per layout option. Phone: bottom bar. Same entries, same order from
  `/sdui/navigation`.
- **Shelf screens (Home, library, collection):** hero (billboard on TV and large screens) with its buttons one stop,
  shelves under it with a peek of the next card, See all as the last card of a shelf; a grid page keeps its filter
  bar as the first Stage row and a **Dock** with sort, filter, view and jump-to-letter on TV.
- **Detail pages:** primary action (Play or Resume) holds default focus; secondary actions (Watchlist, Mark watched,
  Trailer, More) in one row beside it; the options key opens the same actions as a sheet; seasons, tracks, extras and
  credits are Stage rows below. (Credits themselves are S12's.)
- **WittyTV, every theme and platform.** Four fixed places, always the same:
  1. **Preview** (live picture, now playing info) at the theme's chosen side. OK on it goes full screen.
  2. **Grid** (channels by time). Focus lands on the playing or first channel's now cell. Left and Right move through
     time and past the edge page the window by `window / 2`; Up and Down move channels and past the edge page by
     the channel page size (25, 50, 75, 100 or All). The now line and the time header stay visible.
  3. **Dock** under the grid, one row of buttons that never moves: **Look, Day (jump), Channels (set and page size),
     Filter and favourites, Recordings, Record or Series**. Each shows its key glyph. Reached with Down from the last
     channel row, with the options key from anywhere, or with Start; Up returns to the same cell.
  4. **Banner and mini guide** inside the player: OK shows the banner (what's on, next, channel number, record dot);
     Up and Down change channel through the current set; Left opens the mini guide (3 rows); Right opens the Dock's
     audio, subtitle, quality and Look. Back closes the topmost.
  Every WittyTV theme (modern, classic, satellite, teletext, listings, bigpicture, outline, compact, custom) keeps
  its own colours, fonts and cell shapes, but is drawn on these four places and the same tokens (`tv.*` units,
  `focus`, `elevation`). Themes may restyle, not rearrange.
- **Player:** one control bar, same order everywhere (previous, back 10, play, forward 30, next | audio, subtitles,
  quality, speed, more). The timeline is reachable with Up from the bar; Left/Right on it seek, with the thumbnail.
  Skip intro takes default focus when it appears.
- **Settings:** hand-built, untouched structurally. It takes the new tokens (colour, type, focus) like everything
  else and nothing more.

## 5. Themes

The eight built-in themes (Witty, Midnight, Cinema, Evergreen, True black, Light, Paper, High contrast) keep their
palettes and names. What changes: surfaces use the elevation table; every theme gets a `focus` that passes 4.5:1 on all
surfaces and 3:1 against the focused thing's own fill; a TV pass (`tv` block per theme: `ringColor`, `heroScrim`
strength, `tvText` slightly brighter for distance); and `scripts/theme-contrast.py` checks the TV pairs too. The
WittyTV themes keep their identities (`--tv-theme` values) and are rebuilt on the new tokens in the web, Apple and
Android renderers. A theme made by a user or a module scope keeps working: anything it omits is derived.
