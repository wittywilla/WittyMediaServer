# WittyMediaServer next major (written as 0.8.0-alpha): plan

> **Status on 2026-11-04**
>
> **Planned** (ideas, no release yet): [library order](https://github.com/wittywilla/WittyMediaServer/discussions/27), [right-click menus](https://github.com/wittywilla/WittyMediaServer/discussions/28), [deep customisation](https://github.com/wittywilla/WittyMediaServer/discussions/29), [watch together](https://github.com/wittywilla/WittyMediaServer/discussions/32), [local AI for photos](https://github.com/wittywilla/WittyMediaServer/discussions/33), [channel languages](https://github.com/wittywilla/WittyMediaServer/discussions/49), [more ways to install](https://github.com/wittywilla/WittyMediaServer/discussions/37), [native client parity](https://github.com/wittywilla/WittyMediaServer/discussions/61), [more from tuners](https://github.com/wittywilla/WittyMediaServer/discussions/50), [Blu-ray secondary audio](https://github.com/wittywilla/WittyMediaServer/discussions/59).

The owner: "For the next major version of WittyMediaServer (future release, not priority right now), easily customize the order of libraries across the top and side in a customization menu. Allow the ability to right click on those library listings in a web browser and have easy access to settings and the ability to edit metadata / refresh metadata. Make this as extensive as all the customization options available on other providers."

The version number is the owner's to choose. It's still an alpha: the project stays in alpha until every feature the owner wants is at least somewhat implemented. Not built. Not tested.

---

## Headline: navigation and customisation

Full design: [../design/library-navigation-customisation.md](../design/library-navigation-customisation.md).

1. **One customisation menu** for the top bar and the side menu: order, show or hide, group, pin, rename for this server, icons.
2. **A context menu on every library listing** and every item card: right-click on the web, long-press on touch, the menu button on a remote or controller, Shift+F10 and the context-menu key on a keyboard.
3. **Customisation as deep as the best media servers offer, and more:** home rows, per-profile layouts, default sorts and views per library, hidden libraries, per-library looks, and saved layouts that can be reset to stock.

These were partly started in 0.6.0-alpha: the top bar already has a **More** overflow and customising, from the owner's line about a big top bar. This plan extends that, it doesn't replace it.

## Also planned for this major

These need more than an alpha's incremental work, and the existing roadmap already lists them:

| Feature | Notes |
|---|---|
| **Watch together** | A shared, synchronised player across profiles and devices. The WittyTV live sync work (shared clock, program date-time) is the base it builds on. Best built with real networks to test across |
| **Local AI plan document** | Image recognition for photos first. The placeholders already exist (**People & places**, `GET /api/photos/ai`). On-device only, off by default, a model the admin downloads, with its licence shown |
| **Module API 4 as the minimum** | Raise `MinAPI` to 4, after 0.7.x carried API 3 modules unofficially |
| **Release channels in every module** | Every first-party module publishing on alpha, with a beta channel opened for the ones closest to ready |

| **Tuners** | Windows BDA tuning, dish switches on Linux DVB, a viewer and a recording sharing one tuner |
| **Blu-ray** | Secondary audio and picture in picture mixed in. MVC 3D stays blocked on an MVC decoder |
| **Packaging** | One Windows installer for server and client together; apt and dnf repositories hosted; Arch, Flatpak, Snap |
| **Language and subtitles on TV channels** | The shared channel stream carries every audio language and text subtitle as renditions, and each viewer chooses, remembered across programmes. See [../design/channel-audio-and-subtitles.md](../design/channel-audio-and-subtitles.md) |

| **Updates for every kind of install** | macOS pkg after notarisation, Linux and FreeBSD commands, Docker help, going back after a failed update, and automatic updates at a quiet hour (off by default). See [../design/server-updates.md](../design/server-updates.md) |

## What 0.8.0 changes for apps

- The library order and hidden state is **per profile**, kept on the server, and served by `GET /api/me/ui` (where `tvLook` already lives), so every app can follow it.
- The context menu's actions are a list from the server (`GET /api/items/{id}/actions`, `GET /api/libraries/{id}/actions`), so apps don't hard-code who may do what.
- `apiRevision` moves. Old apps keep working: they get the default order and no context menu.
